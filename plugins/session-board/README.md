# session-board

A Claude Code mod for people who run many sessions at once: a task brief at the start, an Acceptance screen and an
interactive HTML report at the end, and a task folder that survives compaction. The board speaks Russian; the ledger
Claude reads is in plain English. Install and safety: see the [main README](../../README.md).

---

Доска сессии для тех, кто ведёт много сессий Claude Code сразу. Главная идея — **два касания на задачу**: в начале
ты даёшь всё на входе, в конце — всю обратную связь. Между ними Claude работает сам и зовёт тебя, только когда упёрся.

```
Поставить задачу ─► Claude задаёт все вопросы разом ─► задание ─► [Старт]
   ─► Claude работает сам (зовёт тебя, только когда упёрся) ─► сдача
   ─► Приёмка ─► Принять / Принять с правками / Вернуть
   ─► Дальше ─► Переделать / Дополнить / Новая задача
```

## Как идёт задача

1. **Задание.** Ты описываешь задачу своими словами. Claude задаёт все недостающие вопросы одним списком и
   записывает задание: цель, результат, 2–5 проверяемых пунктов «готово, когда», правила и запреты, что вне рамок,
   материалы и полномочия. Ты проверяешь задание на доске и жмёшь **«Старт»**.
2. **Полномочия** — что Claude делает сам, а что только с тобой:

   | Уровень | Claude сам | Только с тобой |
   |---|---|---|
   | осторожно | читает, ищет, правит файлы задачи, гоняет тесты | зависимости, коммиты, push, удаление, публикация, деньги, смена цели |
   | обычно | всё из «осторожно», dev-зависимости, коммиты в рабочую ветку | push, публикация, удаление чужого, деньги, смена цели |
   | смело | всё из «обычно», push в рабочую ветку, pull request | слияние в main, публикация наружу, удаление, деньги, смена цели |

   Уровень проекта по умолчанию лежит в `.claude/tasks/policy.json`.
3. **Работа.** Действие за рамками полномочий приходит карточкой «Нужен ты». Остальные развилки Claude решает сам и
   записывает решение — на приёмке его можно отменить.
4. **Сдача.** Claude сам проверяет каждый пункт и сдаёт работу: по каждому пункту одна простая фраза, доказательства
   свёрнуты под кнопкой. Отдельно — «Нужно от тебя», что не сделано, как проверить самому.
5. **Приёмка.** Ты отмечаешь «не так» или оставляешь комментарий (молчание значит «верно») и выбираешь вердикт:
   - **Принять** — задача закрыта, отчёт собран заново;
   - **Принять с правками** — Claude вносит правки одним заходом, и задача закрывается без новой приёмки
     (кнопка появляется, только когда есть хоть одна правка);
   - **Вернуть** — Claude исправляет всё и сдаёт снова.

   Любое замечание можно сделать **правилом проекта**: оно попадёт в `.claude/tasks/RULES.md`, и Claude получит его в
   каждой следующей сессии в этом проекте.
6. **Дальше.** После «Принять» сессия продолжается. На экранах «Приёмка» и «Задание» и по кнопке «Что дальше» на
   полосе — три пути:
   - **Переделать** — та же задача снова в работе: твой текст и есть указание;
   - **Дополнить** — та же задача, твой текст становится новым пунктом «готово, когда»;
   - **Новая задача** — отдельная задача со своим заданием и «Старт».

   «Переделать» и «Дополнить» идут в работу сразу, без «Старт»: та же папка, новый раунд, запись в `feedback.md`,
   потом снова сдача и приёмка. Можно и просто написать в чат: Claude сам поймёт, переделка это, дополнение или новая
   задача.

## Свободный режим

Не каждая сессия — одна задача. Иногда хочется обсудить, побрейнштормить, попробовать прототип, переделать, сделать
что-то вне тикетов. Для этого есть **«Свободный режим»**: задания, критериев и приёмки нет, Claude работает как
партнёр — предлагает варианты, спрашивает, быстро пробует.

- **Включить** можно в любой момент: кнопка «Свободный режим» на экране «Задание» или слово «Свободный режим» в чате.
  Идущая задача встаёт на паузу: её папка остаётся, она ждёт в «Начатых задачах», «Продолжить здесь» её возвращает.
  Работа без задания просто продолжается в свободном режиме.
- **Идеи.** Claude записывает идеи на доску: ○ идея, ● пробуем, ✓ оставили, ✗ отбросили (с причиной). Их видно в
  «Ходе» и на полосе: «свободный режим · идей 5 · оставили 2».
- **Итог.** Кнопка «Подвести итог» или слово «Итог» в чате. Claude доводит каждую идею до статуса и подводит итог:
  что оставили, что отбросили и почему, что не решили, какие решения приняли, что дальше. Итог — на экране «Итог»
  и в `summary.md` в папке сессии. Вердикта нет.
- **Дальше** — новая задача («Поставить задачу»), новый свободный режим или «Продолжить здесь» у задачи на паузе.

С notion-tasks свободному режиму тикет не нужен; при итоге каждая оставленная идея, которую ещё надо доделать,
становится тикетом.

## Экраны

| Где | Отвечает на вопрос | Что там |
|---|---|---|
| Полоса над полем ввода | Работает ли Claude и нужен ли я? | одно состояние и одна кнопка: «Поставить задачу», «шаг 3 из 7», «нужен ты · 2», «Принять работу» |
| Полоса под длинным ответом | Можно понять это быстрее? | «показать иначе: STE / Схема / HTML / Анимация» — лестница форматов Карпаты; кнопка отправляет просьбу в сессию, полоса прячется при следующем сообщении |
| Задание | Понимаем ли мы задачу одинаково? | задание, пункты со статусом, правила, полномочия; без задачи — шаблон и незаконченные задачи проекта («Продолжить здесь») |
| Ход | Где мы сейчас? | карточки «Нужен ты», главное сейчас, цели и шаги, что копится на приёмку |
| Приёмка | Можно ли принимать? | вывод одной строкой, «Нужно от тебя», пункты с доказательствами, решения Claude, допущения, риски, вердикт |
| Журнал | Можно ли этому доверять? | почему (цепочки, решения, тупики), ходы, файлы с изменениями, что Claude помнит после сжатия |
| Спросить | Объясни мне | вопрос по всей сессии; ответ не попадает в переписку; «проще», «схемой», «проверь меня» |

У строк журнала есть кнопки «зачем это?», «почему так?», «что изменилось?», «устарело». Заметка «для Claude»
уходит вместе с твоим следующим сообщением или сразу по «Отправить сейчас».

## С lean

Если стоит плагин [lean](../lean) (Claude пишет минимум кода), доска встраивает его в каждую точку задачи. Доска
узнаёт lean по строке, которую его хук печатает при старте сессии. Без lean ничего из этого не появляется.

| Где | Что появляется |
|---|---|
| Задание | Строка «Код»: lite / full / ultra / выкл рядом с полномочиями. Пока уровень не выбран, действует настройка lean. «Старт» передаёт уровень Claude; смена во время работы уходит заметкой. Ниже — «Срезанные углы в проекте»: сколько меток `lean:` в коде (`git grep`, только чтение) и кнопка «показать список». |
| Ход | В «Копится на приёмку» — «не построено N». |
| Сдача | Перед сдачей Claude проверяет дифф задачи на лишнее, как lean-review, и записывает находки на доску. Код при этом не правит. Итог — одна строка «Самопроверка на лишнее»; если её нет, приёмка так и пишет. |
| Приёмка | Раздел «Не построено»: ◇ пропущено (кнопка «добавить сейчас»), ◆ срезано, то есть метка `lean:` («сделать полностью»), − лишнее («убрать»). Отмеченное уходит правкой в общем вердикте. «Проверить на лишнее» просит Claude проверить работу ещё раз. |
| Отчёт и телефон | Блок «Что не построено и когда добавить» в отчёте и в текстовой карточке `/board`. |

## С notion-tasks

Если стоит плагин [notion-tasks](../notion-tasks) и проект привязан к доске Notion, задание можно взять из тикета:
`/notion-tasks:take`. Ссылка на тикет — первое правило задания. «Старт» ставит тикету статус «в работе», «Принять» —
«готово» и пишет в тикет отчёт. «Переделать» и «Дополнить» возвращают тикет «в работу», следующая приёмка снова
закрывает его. Всё, что всплыло по ходу, Claude заводит новыми тикетами; на приёмке они видны
решениями со ссылками. Код доски для этого не меняется.

С плагином [obsidian-tasks](../obsidian-tasks) так же работает доска роадмапа в Obsidian: `/obsidian-tasks:take`,
статус — колонка Kanban или свойство заметки, отчёт — раздел в конце заметки тикета.

## С телефона

Если ведёшь сессию с телефона, планшета или из браузера через Remote Control (сессия идёт на Mac, устройство к ней
подключено), доска работает текстом. Моды рисуют только в терминале и в приложении на Mac ([документация, «Where
mods run»](https://code.claude.com/docs/en/plugins/mods/overview)), поэтому на телефоне нет ни панели, ни полосы.

- `/board` выводит доску текстом: задание, «Нужен ты», пункты «готово, когда» с ✓ и ✗, что ответить дальше. Следом
  приходит вопрос с кнопками на следующий шаг: «Старт / Поправить задание», «Принять / Вернуть / Принять с правками»,
  после приёмки «Переделать / Дополнить» или вопрос Claude. Свой текст пишешь в поле «Other».
- Короткие слова в чате нажимают кнопки доски: «Старт» — когда задание ждёт старта; «Принять», «Вернуть: что
  поправить» и «Принять с правками: что поправить» — на приёмке; «Переделать: что не так» (или «Вернуть: …») и
  «Дополнить: что добавить» — после приёмки; «Свободный режим» — в любой момент; «Итог» — в свободном режиме. В более длинной фразе слова не срабатывают.
- Пуш приходит, когда задание ждёт «Старт», когда нужен твой ответ и когда работа сдана, с подсказкой, что ответить.
  Выключить — настройка `push`. Пуш не показывается, пока приложение Claude открыто на экране.

## Отчёт

`report.html` в папке задачи — одна страница без сети. Это **схема метро сессии**: каждая цель — цветная линия по
ходам слева направо, шаги — станции, решения — пересадки, тупики — серые упоры, пункты приёмки — квадраты, которые
зеленеют, когда пункт доказан. При открытии сессия прорисовывается сама; «Проиграть сессию» повторяет это; номера
ходов внизу и стрелки ← → переводят на нужный ход. Клик по станции открывает детали: что это, почему так решили, что
отвергли, доказательства, откуда пришло. Ниже — развилки и тупики, что проверено, изменения по файлам.

Отчёт собирается при сдаче, по кнопке «Открыть отчёт» и по `/board-report`.

## Память и файлы

```
.claude/tasks/
  .gitignore            # папки задач не попадают в git
  policy.json           # уровень полномочий проекта (только твой, локальный)
  RULES.md              # правила из приёмок (только твои, локальные)
  2026-10-03-<название>/
    task.md             # задание
    ledger.json         # журнал целиком (его загружает доска)
    ledger.jsonl        # журнал операций
    ledger.md           # журнал на простом английском (его читает Claude)
    board.ru.md         # журнал по-русски
    brief.md            # памятка для Claude после сжатия
    report.html         # отчёт
    feedback.md         # все раунды приёмки
    summary.md          # итог свободного режима
.claude/session-board/<id сессии>/task.json   # какая задача у этой сессии
```

- **Журнал** — дерево: цели, вопросы, гипотезы, шаги, находки, решения (с отвергнутыми вариантами и ценой), тупики,
  допущения, риски, пункты приёмки.
- **Картограф** после каждого хода с работой одним вызовом модели (копия сессии из кэша) дописывает в журнал смысл
  хода. Решения из твоих ответов на вопросы Claude записываются без модели.
- **После сжатия** переписки доска отдаёт Claude памятку с номерами пунктов журнала и путём к папке задачи.

## Для Claude

Инструменты: `task` (записать задание), `submit` (сдать работу или итог свободного режима), `reopen` (вернуть принятую задачу в работу:
переделать или дополнить), `note` (решение, допущение, находка, вопрос, идея),
`ledger_read` (прочитать журнал), `show` (вывести наглядное объяснение в отдельную панель).
Команды: `/board`, `/board-update`, `/board-ask <вопрос>`, `/board-report`.

## Настройки

`claude plugin configure session-board@oshn`: `update` (`every-turn` или `manual`), `minTools`, `autoOpen`,
`injectAfterCompact`, `push`. Описание — в [главном README](../../README.md#install).

## Безопасность

- Мод работает в твоей сессии с твоими правами: пишет только в `.claude/tasks/` и `.claude/session-board/` проекта,
  запускает `git` только на чтение, `mv` внутри папки задачи и команду открытия файла (`open` на macOS, `explorer`
  на Windows, `xdg-open` на Linux), в сеть не ходит. Пуши он отправляет через
  инструмент Claude Code `PushNotification`; текст пуша — название задачи или вопроса.
- Политику, правила и папки задач, которые пришли с клонированным репозиторием (git их отслеживает), доска не
  применяет и сообщает об этом.
- Правила, которые картограф вывел из вывода инструментов, Claude получает с пометкой «не подтверждено».
- «Открыть» открывает только файлы проекта; то, что macOS запустила бы (`.command`, `.app`), показывается в Finder.
  На Windows двойной щелчок запускает `.py`, `.js`, `.bat` и многое другое, поэтому там «Открыть» только показывает
  файл в Проводнике. Отчёт открывается в браузере на всех системах.

Подробно — [аудит безопасности](../../docs/security-audit.md).

## Ограничения

- У каждой сессии своя доска; общей очереди всех сессий нет.
- API модов в раннем доступе и может меняться.
- С `update: every-turn` каждый ход с работой стоит один вызов модели.
- Видео-объяснения — во второй версии.
